Internal Developer Reference

Adding a New Game
to Aastheen

The balloon project is a container. It holds multiple games as Unity scenes. Bootstrap is the login screen. You are dropping a new game into that container and wiring it to the doctor's phone app. That's it.

Part 1

Unity — 6 Steps

1
Copy the game into the balloon project

The balloon folder is your workspace. Everything goes inside it.

  • Open Documents/VR_games/balloon in Unity Hub
  • Drag your game's entire folder (scenes, scripts, assets, prefabs) into Assets/
  • Wait for Unity to finish reimporting — the progress bar at the bottom must complete
2
Clean up the scene

Remove things that don't work here. Add the things Aastheen needs.

  • Open your game's main scene
  • Delete any FlutterBridge, PoseLogger, or LogFilePathDisplay objects
  • Make sure the scene has an OVRCameraRig — if not, copy one from ballooon.unity
  • Add a Canvas (World Space) with a Start button and a Score / Timer text
3
Create [YourGame]GameManager.cs Assets/Scripts/Verse/

This is the only new script you write. It does exactly 3 things:

1. Reads the settings the doctor sent (duration, difficulty, etc.) from PlaylistManager
2. Tracks the session — score, reps, elapsed time
3. When the session ends, posts results to the cloud via VerseClient
// Minimal structure — ask GPT to fill this in for your game public class MyGameGameManager : MonoBehaviour { void Start() { // 1. Read settings var settings = PlaylistManager.Instance? .CurrentPrescription?.myGameSettings; // 2. Start session timer, apply settings } void OnSessionEnd() { // 3. Post results VerseClient.Instance.PostSessionResults(metrics); } }
4
Add to VerseDataModels.cs Assets/Scripts/Verse/VerseDataModels.cs

Scroll to the bottom of the file and add two classes:

// What the doctor controls (sent to Quest) [Serializable] public class MyGameSettings { public int sessionDuration = 300; // seconds public int repTarget = 10; public float difficulty = 1.0f; // add more as needed } // What gets sent back to the cloud [Serializable] public class MyGameMetrics { public int total_score; public int reps_completed; public float accuracy; // add more as needed }

Also add public MyGameSettings myGameSettings; inside the existing VersePresciption class.

5
Add to PlaylistManager.cs Assets/Scripts/Verse/PlaylistManager.cs

Find the switch block that loads scenes. Add one line:

case "mygame": SceneManager.LoadScene("MyGameSceneName"); break;

The game name string (e.g. "mygame") must exactly match what the Flutter app sends in the prescription.

6
Add scene to Build Settings
  • Open your game's scene in Unity
  • File → Build Settings → Add Open Scenes
  • Your scene now appears below Bootstrap and ballooon in the list
  • Make sure it is enabled (checkbox ticked)
Part 2

Flutter — 3 Steps

7
Add settings model lib/models/verse_models.dart

Mirror what you put in Unity's VerseDataModels.cs:

class MyGameSettings { final int sessionDuration; final int repTarget; final double difficulty; MyGameSettings({ this.sessionDuration = 300, this.repTarget = 10, this.difficulty = 1.0, }); Map<String, dynamic> toJson() => { 'sessionDuration': sessionDuration, 'repTarget': repTarget, 'difficulty': difficulty, }; }
8
Add game chip + settings lib/pages/add_session.dart

Find where the Balloon and Garden chips are. Add yours the same way, then add sliders below for each doctor-controlled setting.

  • Add a chip with your game's name and a distinct color
  • Show its settings sliders only when that chip is selected
  • Include the game name string (e.g. "mygame") in the prescription payload
9
Show results lib/pages/patient_info.dart

Find the session history card. Add a row for each metric your game returns — score, reps, accuracy, etc. Same pattern as Balloon's metrics display.

Part 4

What NOT to Add

✕ Ghost hands or InactivityGuide — no hint/guide system of any kind
✕ FlutterBridge or WebSocket relay — all communication goes through VerseClient (REST)
✕ Unity MCP or dev agent tools — no McpPlugin, no DevAgentSettings in your scene
✕ Editing ballooon.unity or Bootstrap.unity — those scenes are locked, do not touch them
✕ Files outside Assets/Scripts/Verse/ and Assets/Scenes/ — don't touch other scripts or settings

Part 6

How Balloon Was Made Aastheen-Compatible

The balloon game originally talked directly to Flutter over WebSocket (V1). It was upgraded to work with the Verse cloud system (V2) while keeping V1 working. Your new game only needs V2 — simpler.

V1 — Original (WebSocket)
Flutter runs a WS server on port 8765
Unity connects as WS client on start
Settings arrive as a JSON message
Results sent back over the same socket
Doctor and Quest must be on same WiFi
V2 — Verse (Cloud REST)
Quest enters 5-digit code in Bootstrap
Backend returns prescription + JWT
PlaylistManager stores the prescription
Game reads settings from PlaylistManager
VerseClient POSTs results to cloud on end

What was changed in balloon to support V2:

  • Added VerseClient.cs, PlaylistManager.cs, VerseDataModels.cs in Assets/Scripts/Verse/
  • Added Bootstrap.unity scene as the first scene (scene index 0)
  • GameManager.cs checks if PlaylistManager exists — if yes, uses V2 settings; if no, uses V1 WS settings
  • Both paths produce the same game experience — V1 still works for older setups

For your new game — only write V2. No need for WebSocket fallback. Just read from PlaylistManager and post to VerseClient.

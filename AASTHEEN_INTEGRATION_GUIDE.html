🏗 Architecture

Aastheen has two protocol generations. Both must coexist — V1 must keep working while V2 is being built.

V1 — Local WebSocket (running)

Flutter runs a WS server on port 8765. Quest discovers Flutter via UDP broadcast on port 8766. No cloud, no auth. Doctor's laptop must be on the same hotspot.

Flutter (WS Server :8765)
    ↕  UDP discovery :8766
Quest (WS Client)
V2 — Verse Cloud Auth (in progress)

Quest enters a 5-digit prescription code → REST to aastheen.onrender.com → gets session JWT + prescription → auto-launches game playlist. No Flutter required at runtime.

Quest → POST /prescriptions/verify
  ← session_token + BalloonSettings
Quest → POST /sessions/{id}/results
⚠ Rule — Backward Compatibility

Every new game must work in both modes. In Start(), check PlaylistManager.Instance?.HasSession. If true → V2 path. If false → wait for V1 WS prescription. Never remove V1 code.

⚡ 5-Minute Quickstart

Minimum steps to make any existing Unity VR game Aastheen-compatible from scratch.

Copy the core scripts

From balloon/Assets/Scripts/, copy these into your project:

WSClient.cs WSDataModels.cs WebSocket/WebSocket.cs InactivityGuide.cs GhostHandGuide.cs Verse/VerseClient.cs Verse/PlaylistManager.cs Verse/VerseDataModels.cs UnityMainThreadDispatcher.cs

Drop the Meta SDK prefabs into your scene

In Unity: GameObject → XR → OVR Camera Rig, or use Building Blocks panel (Window → XR → Building Blocks). Add: Camera Rig, Hand Tracking (L+R), Controller Tracking. These give you head/hand position for free.

Create a GameManager implementing the contract

Add a single GameManager MonoBehaviour. It needs three methods — the protocol won't call anything else:

public void OnPrescriptionReceived(PrescriptionMessage msg) // store settings
public void OnCommand(string command)              // "start"|"stop"|"pause"|"reset"
public void OnSensorData(float rotation, float speed, string warning)

Add WSClient to GameManager

Select your GameManager in the Hierarchy → Add Component → WSClient. Set Server Port: 8765, Debug Direct Connect: false. WSClient will auto-discover Flutter via UDP and route all messages to GameManager.

Add InactivityGuide + GhostHandGuide prefab

Select GameManager → Add Component → InactivityGuide. Drag GhostHandGuide.prefab into the scene, then drag that instance into the Ghost Hand slot. Done — guide appears after 15s of inactivity automatically.

Add V2 Verse singletons to Bootstrap scene

In the Bootstrap scene only, create empty GameObjects and attach: VerseClient (DontDestroyOnLoad), PlaylistManager (DontDestroyOnLoad), UnityMainThreadDispatcher. These survive scene loads and auto-wire into every game scene.

🥽 Meta SDK Prefabs — Use These First

The Meta XR SDK ships with Building Blocks — one-click prefab systems that handle the hard parts. Never build camera rigs, hand tracking, or grab systems from scratch.

Finding Building Blocks

Window → XR → Building Blocks in the Unity menu bar. Each block auto-installs its dependencies and sets up the correct hierarchy. You can also use GameObject → XR for quick prefab placement.

⚠ Tracking Origin — Always Set EyeLevel

On the OVRManager component (sits on OVRCameraRig), set Tracking Origin Type = Eye Level. Floor-level causes the camera to appear at floor height in the headset. This must be set per-scene.

✓ Pattern used in Garden game — CanGrabNotifier.cs

The watering can uses Oculus.Interaction.Grabbable + CanGrabNotifier.cs. The notifier listens to WhenPointerEventRaised events to set isGrabbed = true/false. Any rehab game with a grab object should replicate this exact pattern.

// CanGrabNotifier.cs — attach alongside Grabbable
Grabbable grabbable = GetComponent<Grabbable>();
grabbable.WhenPointerEventRaised += HandlePointerEvent;

void HandlePointerEvent(PointerEvent evt) {
    if (evt.Type == PointerEventType.Select)   isGrabbed = true;
    if (evt.Type == PointerEventType.Unselect) isGrabbed = false;
}

📌 API Note — FindObjectOfType in static context

In static methods and MCP script-execute bodies, use the full form: UnityEngine.Object.FindObjectOfType<T>(). In MonoBehaviour methods, FindObjectOfType<T>() works directly. Use FindObjectsByType<T>(FindObjectsSortMode.None) for multi-result queries (new API, replaces FindObjectsOfType).

🌐 Network Layer

V1 — WebSocket (Local Flutter Server)

All V1 game communication goes through a single WSClient.cs component. Copy it and add it to your GameManager — that's the entire integration.

FileRoleAction needed
WSClient.csUDP discovery + WS connection + message routingAdd Component to GameManager. Set serverPort=8765
WebSocket/WebSocket.csNativeWebSocket implementation (works on Android)Copy as-is, no changes
WSDataModels.csSerializable message classesAdd your game's extra fields here. Never remove existing fields.
// In your GameManager — WSClient will call these methods automatically:
public void OnPrescriptionReceived(PrescriptionMessage msg) { ... }
public void OnCommand(string command) { ... }
public void OnSensorData(float rotation, float speed, string warning) { ... }

// To send data back to Flutter:
WSClient.Instance?.SendSessionResult(sessionResultMessage);
WSClient.Instance?.SendRepDone(repDoneMessage);
How UDP discovery works

Flutter broadcasts AASTHEEN_SERVER:8765 on UDP port 8766 every 2 seconds to both 255.255.255.255 and the subnet broadcast (computed from the active NIC). Quest's WSClient listens on UDP 8766, extracts the IP, then opens ws://<ip>:8765/ws/balloon. Zero hardcoded IPs in production. Change /ws/balloon to /ws/yourGame in WSClient.ConnectWebSocket().

V2 — Verse Cloud Auth

V2 requires three singletons in the Bootstrap scene only. They persist across all scene loads via DontDestroyOnLoad.

VerseClient.csVerseClient (Bootstrap)REST calls to aastheen.onrender.com. BaseUrl loaded from PlayerPrefs, falls back to Inspector default.

if (PlaylistManager.Instance != null && PlaylistManager.Instance.HasSession) {
    // V2 path — load prescription from PlaylistManager
    BalloonSettings s = PlaylistManager.Instance.Settings;
    OnPrescriptionReceived(new PrescriptionMessage { ... });
    StartSession();
}
// else: V1 path — wait for WSClient to receive prescription over WS

📋 GameManager Contract

Every Aastheen game scene must have exactly one GameManager (or equivalent) that implements this interface. WSClient and Verse both talk to it.

// ── Minimum GameManager interface ──────────────────────────────
public class GameManager : MonoBehaviour {
    public static GameManager Instance;    // singleton

    // Called by WSClient (V1) or by Start() reading PlaylistManager (V2)
    public void OnPrescriptionReceived(PrescriptionMessage msg);

    // Called by WSClient on {"type":"command","command":"start|stop|pause|reset"}
    public void OnCommand(string command);

    // Called by WSClient on {"type":"sensor"} — EMG/IMU readings
    public void OnSensorData(float rotation, float speed, string warning);

    // Called when the game ends — POST results to backend
    private void EndSession(); // internal, calls VerseClient.SubmitResults()
}
⚠ Critical — OnPrescriptionReceived must NOT auto-start

Only store parameters in OnPrescriptionReceived. The session starts only when OnCommand("start") arrives (V1) or when StartSession() is called directly from Start() (V2). Mixing these causes double-starts.

🎬 Scene Requirements

Every game scene must have these GameObjects present. Anything not listed is game-specific and optional.

  • OVRCameraRig — with TrackingOriginType = EyeLevel on OVRManager
  • [BuildingBlock] Hand Tracking left + right — via Building Blocks panel
  • [BuildingBlock] Controller Tracking (if using controllers)
  • GameManager — implementing the 3-method contract above
  • WSClient (component on GameManager) — serverPort=8765, debugDirectConnect=false
  • InactivityGuide (component on GameManager) — ghostHand wired, timeout=15f
  • GhostHandGuide (instance in scene) — dragged into InactivityGuide.ghostHand slot
  • UnityMainThreadDispatcher — standalone GameObject, only if V2 Verse used
  • EventSystem with OVRInputModule (required for UI button clicks in VR)
  • Canvas with OVRRaycaster (instead of GraphicRaycaster) for any World Space UI
📌 OVRRaycaster — Required for all World Space UI

Replace Unity's default GraphicRaycaster with OVRRaycaster on every World Space Canvas. Without it, OVR controller/hand rays won't hit UI elements. The Bootstrap scene was broken for weeks because of this — OVRComprehensiveInteractionRig + GraphicRaycaster were the missing pieces.

👻 Ghost Hand Guide (Inactivity-Triggered)

After N seconds of no correct action, a semi-transparent ghost hand appears at the current target's position, pulses, and tracks the target in real-time. It disappears instantly when the player succeeds. Fully configurable from the Flutter prescription.

Guided Mode ON (default)

Player doesn't pop a balloon for 15s → ghost appears at that balloon, tracks its movement toward player, pulses blue → player pops → ghost fades out immediately.

Guided Mode OFF

Set guidedMode = false in prescription (via Flutter) or on the InactivityGuide component. Guide never appears. Good for experienced patients or accuracy-testing sessions.

Scripts

GhostHandGuide.cs — the visual

// Attach to your ghost prefab. Assign ghostRenderers[] in Inspector.
GhostHandGuide guide = GetComponent<GhostHandGuide>();
guide.SetTarget(balloonTransform); // tracks live Transform
guide.Show();   // fades in, pulses alpha + scale
guide.Hide();   // fades out, deactivates

// Inspector fields:
public Renderer[] ghostRenderers;      // all renderers on the ghost
public float maxAlpha        = 0.55f; // fully visible alpha
public float minAlpha        = 0.15f; // pulse low point
public float pulseSpeed      = 2f;
public float floatAmplitude  = 0.04f; // gentle bob in Y
public float scalePulseAmount = 0.08f;

InactivityGuide.cs — the timer logic

// Attach to GameManager. Wire ghostHand in Inspector.
InactivityGuide.Instance?.OnSessionStart();      // call in GameManager.StartSession()
InactivityGuide.Instance?.OnSessionEnd();        // call in GameManager.EndSession()
InactivityGuide.Instance?.NotifyCorrectPop();   // call on any correct action
InactivityGuide.Instance?.OnNewTarget(t);       // call when new target spawns (resets timer)
InactivityGuide.Instance?.OnTargetGone();       // call when target missed/despawned

// Inspector fields:
public float          inactivityTimeout = 15f; // set from prescription at runtime
public bool           guidedModeEnabled = true;
public GhostHandGuide ghostHand;               // drag scene instance here

Prescription fields (auto-wired)

// In PrescriptionMessage / BalloonSettings / GardenSettings:
public bool  guidedMode      = true;  // false = disable entirely
public float guideTimeoutSec = 15f;   // 10-30 recommended for rehab

// GameManager.OnPrescriptionReceived sets these automatically:
InactivityGuide.Instance.guidedModeEnabled = msg.guidedMode;
InactivityGuide.Instance.inactivityTimeout  = msg.guideTimeoutSec;

Scene Setup — Step by Step

Create the ghost material

Right-click Assets/Materials → Create → Material. Shader: Universal Render Pipeline/Lit. Set Surface Type = Transparent, Base Color = (R:50 G:150 B:255 A:115). This gives the translucent blue glow.

Build the ghost prefab

Create an empty GameObject named GhostHandGuide. Add a child Sphere (scale 0.12) and optionally a second smaller Sphere (scale 0.09). Remove colliders from both. Assign the ghost material. Add GhostHandGuide.cs to the root. Drag both MeshRenderers into ghostRenderers[].

Wire in the scene

Drag the prefab into the scene hierarchy. Select GameManager → Add Component → InactivityGuide. Drag the scene instance of GhostHandGuide into the Ghost Hand slot.

Call the four events from your game logic

When a target appears → OnNewTarget(target.transform). When correctly cleared → NotifyCorrectPop(). When target despawns missed → OnTargetGone(). That's it — the guide handles the rest.

Garden Game Variant — Phase-Aware Guide

The garden game has two sequential phases per task: grab the can → tilt to water. The guide needs to know which phase is active to show the right gesture.

// In GardenGameManager or WaterController — call per phase:
if (!grabNotifier.IsGrabbed()) {
    // Phase 1: guide should appear near the watering can
    InactivityGuide.Instance?.OnNewTarget(wateringCanTransform);
} else if (!rotationTracker.isWatering) {
    // Phase 2: guide should appear near the player's wrist
    InactivityGuide.Instance?.OnNewTarget(rightHandTransform);
}

// When watering detected (correct action):
InactivityGuide.Instance?.NotifyCorrectPop();

📦 APK Build Checklist

  • Target: Android, API Level 29+ — Quest runs Android. Set in Player Settings → Android
  • Texture Compression: ASTC — required for Quest 3S. Use ASTC, not ETC2
  • IL2CPP scripting backend — Mono sometimes fails on Quest. Use IL2CPP for release APKs
  • Scenes in Build Settings — Bootstrap (index 0), ballooon (index 1), Game_Garden (index 2). ORDER MATTERS for PlaylistManager
  • Clean Build checkbox — ALWAYS tick "Clean Build" when you've added or renamed serialized fields (new fields cause layout mismatch error if cache is stale)
  • Meta XR SDK namespace patch — if you get "duplicate class com.oculus.Integration", run Tools → Patch Meta XR AAR Namespaces (AARNamespacePatcher.cs in Assets/Editor/)
  • Android permissions in AndroidManifest.xml — INTERNET, ACCESS_NETWORK_STATE, ACCESS_WIFI_STATE, CHANGE_WIFI_MULTICAST_STATE. Flutter engine doesn't add all of these automatically in release
  • OVRCameraRig TrackingOriginType = EyeLevel — check per scene before building
  • GhostHandGuide prefab wired — GameManager → InactivityGuide → Ghost Hand slot not empty
  • Install: adb install -r yourapp.apk OR use SideQuest. Enable "Developer mode" in Meta phone app first

🔍 Debug Checklist

Quest not connecting to Flutter (V1)

  • Quest and phone both on Windows laptop hotspot (Windows Settings → Mobile Hotspot)?
  • Flutter app on Game Session screen? (WS server only starts in initState)
  • Windows firewall rule added? netsh advfirewall firewall add rule name="Quest WS" dir=in action=allow protocol=TCP localport=8765
  • Check logcat: adb logcat -d --pid=$(adb shell pidof com.your.package) | findstr WSClient
    Should see: [WSClient] Searching for Flutter server on port 8766 then [WSClient] Connected → ws://...

Ghost guide not appearing

  • InactivityGuide component on GameManager?
  • Ghost Hand slot filled (GhostHandGuide instance in scene)?
  • guidedModeEnabled = true in InactivityGuide Inspector?
  • OnSessionStart() being called at session begin?
  • OnNewTarget(transform) being called when target spawns?
  • GhostHandMaterial has Surface Type = Transparent?

Water not flowing (garden game)

  • WaterSpout ParticleSystemRenderer has WaterParticle.mat assigned?
  • SpillEffect ParticleSystemRenderer has SpillParticle.mat?
  • WaterController.waterParticles, rotationTracker, spillParticles all non-null in Inspector?
  • CanGrabNotifier on WateringCup? Grabbable component also present?
  • ForearmRotationTracker finding right OVRHand? (Check logs for "Right OVRHand not found")
